# Coding organization example

System-in-focus: an autonomous software-maintenance organization responsible for a product repository.

- S1 consists of independently accountable units for feature delivery, dependency maintenance, and incident repair, each coupled to different parts of the product environment.
- S2 coordinates file ownership, shared test capacity, release windows, and incompatible changes.
- S3 negotiates priorities and budgets, monitors the current portfolio, and reallocates capacity when incidents threaten commitments.
- S3* samples raw patches, test environments, and deployed behavior through a path not controlled solely by the producing unit.
- S4 monitors user needs, dependency ecosystems, security threats, model capabilities, and possible architectural changes.
- S5 preserves product purpose, acceptable risk, and ultimate authority and closes unresolved tension between shipping now and adapting for later.

Any of these functions may be performed by people, agents, deterministic software, or combinations. A CI pipeline contributes to audit only to the extent that its access, independence, and purpose let it challenge normal operational reporting.
